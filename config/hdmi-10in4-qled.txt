# Waveshare 10.4" QLED (10.4HP-CAPQLED): 1600x720, HDMI video, USB-C touch
# Pi OS Trixie (Debian 13), kernel 6.18.50+rpt-rpi-v8, Pi Zero 2 W
# Status: NOT YET VERIFIED on hardware (written 2026-10-30). Update this header once it works.
# Source: Waveshare wiki https://waveshare.com/wiki/10.4HP-CAPQLED
#
# --- /boot/firmware/config.txt -------------------------------------------------
#
# 1. Keep the KMS driver line (the games runner draws through it):
dtoverlay=vc4-kms-v3d
#
# 2. Comment out the whole 2.8" DPI block while the 10.4" is in use. The DPI output
#    always reports "connected", so with it on, fullscreen apps can land on the
#    (absent) DPI panel instead of HDMI:
# dtoverlay=waveshare-28dpi-3b-4b
# dtoverlay=waveshare-28dpi-3b
# dtoverlay=waveshare-28dpi-4b
# dtoverlay=waveshare-touch-28dpi
# dtoverlay=vc4-kms-dpi-2inch8
#
# 3. Usually nothing else: with KMS the Pi reads the panel's EDID and picks 1600x720.
#    Check after boot:   cat /sys/class/drm/card*-HDMI-A-1/modes      (first line should be 1600x720)
#
# --- only if the mode comes up wrong ----------------------------------------------
#
# Under KMS, force it on the kernel command line instead (/boot/firmware/cmdline.txt,
# all on its one line, add a space then):
#     video=HDMI-A-1:1600x720@60
#
# Waveshare's wiki gives these lines, but they're for the old firmware display
# driver (no KMS) and are ignored with vc4-kms-v3d; listed for reference only:
#     hdmi_group=2
#     hdmi_mode=87
#     hdmi_timings=1600 0 80 32 112 720 0 30 3 33 0 0 0 60 0 87000000 0
